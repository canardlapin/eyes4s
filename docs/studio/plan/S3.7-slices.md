# Real backend implementation and acceptance

S3.7 (`bd-01M3DPFHY9YW5BPSJQ8VBBXHVN`) connects Eyes Studio to native
fixation-study analyses. Admission, preview, execution, reporting and inspection
share the library's scientific operations. The acceptance target is the complete
fixture → saved plan → run → Compare → source → reopen → export journey, with
headless, desktop and direct-library agreement. Implementation and focused tests
do not by themselves close S3.7 or gate G1.

## Rules every slice keeps

- **No science in studio.** The real backend calls the library and converts its values into the
  studio protocol types. It never re-derives a count, score, placement or density. Summing
  durations the library has already tallied, or counting rows of a library ledger, is bookkeeping.
  Anything that decides what a fixation, trial or pair *is* stays in eyes4s.
- **Failures are typed values.** Every eyes4s refusal becomes a `BackendError` that names its
  operands: either an existing case, or a new case added in the slice, with its stable code and a
  protocol bump when it changes the wire. An effect fails only on a defect of the backend itself.
- **R is never a dependency.** Scores the real backend serves are compared with
  `fixtures/studio-golden/SCORES.json` (S0.7b), never with an R run.
- **Placement.** `RealStudyBackend` lives in `studio-core` shared sources (JVM and Scala.js).
  `studio-core` gains a compile dependency on `eyes4s-io`, which is cross-built and allowed to use
  effects; today `studio-core` reaches io only from its JVM tests.
  - The backend reads no files. Its datasets arrive as `DatasetRevisionSpec`s from the studio
    document, and its source contents arrive through a host port that the host provides:
    studio-desktop reads files, and JVM tests serve `fixtures/studio-golden`. The port was planned
    as `SourceContents[F]` and is named `DatasetSources[F]` in code.
  - `studio-app` stays pure. It never calls the backend's library code directly; it only receives
    `StudyBackend` responses.
- **Conformance.** `BackendConformanceSuite` supplies the shared contracts for both backends.
  `RealBackendConformanceSuite` runs every current inherited test against the golden files and
  genuine runner jobs. Its explicit qualification list must exactly match the inherited tests;
  newly added contracts fail this guard until qualified. Direct and JSON transport journeys
  retain independent backend sessions across their ordered requests, including preview row reads.

## Native operations

| Operation | Native source and contract |
|---|---|
| Admission and ledger | `FixationCsv.admitInventory`, `FixationEvidence.ledger`, `WindowTally` and `WindowSummary`; source bytes are checked against the recorded SHA-256 before admission. |
| Static preview | Explicit synchronous convenience over a prepared study and completed native counts. Its completed metadata is retained for row reads. |
| Bounded preview | `PreparedStudy.countWork` advances under fixed `WorkQuanta` and the request's page budget. Receipts bind canonical plan/input digests and the exact typed recipe snapshot. |
| Preview rows | Requested inventory queries, including unmatched and unadmitted trials, joined to `StudyCounts.queryPairs`. Row reads never start counting or enumerate another pair schedule. |
| Preview submission | The whole receipt must equal the backend-owned value, its current artifact identities must still agree, and native pairing refusals prevent a job. |
| Jobs and cancellation | The shared eyes4s-fs2 runner supplies progress, final outcomes and cancellation; the backend resource owns its fibers. |
| Result and query facts | Retained native inspection supplies all requested query outcomes and score vectors. Result summaries carry counts and identities; numerical report cells have an explicit spec and scale. |
| Reports | Bound `ReportSources` and native `Report.evaluate` supply grouping, filters, weighting, exclusions, participant values and references. Ordered contrast operands are persisted explicitly. |
| Density grids | Native retained `DensityView` cells preserve their checked geometry. |
| Trial preview | `PreparedStudy.estimate` supplies the fixed 2-degree preview through the runner's frame, initial-fixation, window and weighting pipeline. |
| Trial fixations and source text | `CoordinateProvenance` and `FixationSourceText` retain actual source records, placement and raw text. |

The preview's `CountingWork` reports native schedule work rather than invented
participant completion. The application starts row reads only after the matching
ready receipt. A repeated ready receipt is idempotent; a different preview id,
initial stamp, recipe or declared binding is refused. A refused prepared submission
settles only the exact document run named by that request and never silently retries
through ordinary submission.

Live document synchronization preserves saved dataset and analysis definitions,
while draft edits invalidate current preview rows and trial views. Older cursors
and jobs retain their original snapshots; an older cursor completing cannot
restore rows for the edited draft. A newly requested document run reserves its
explicit ID, including when it differs from the backend's next allocated ID.

Backend result requests return typed pending/deferred job identities. Local host
readers wait on those jobs' real terminal events, leaving the backend available
for cancellation. Closing the reader resource ends its pending reads explicitly.

Concurrent readers of a reopened run share its native recomputation. After source
preparation, reservation rechecks the retained result, refusal and active job under
the submission mutex. A reader whose preparation outlasted that computation gets
the retained result rather than starting another job.

`PreparedStudy.estimate` refuses an unknown or repeated full key explicitly. Its
returned `DensityView` preserves the analysis window's origin and declared angular
cell geometry. The fixture preview also uses this entry point, with the fixture's
recorded sample counts rather than invented samples.

## Reporting and persistence

[Native reporting and saved contrast direction](../REPORTING.md) describes the
report contract and its schema versions. Protocol 1.16 carries scale-free result
facts, optional matched references, explicit contrast operands, native preview work
and recipe-bound receipts. Both ends require the exact protocol version.

Grouping alone does not declare a subtraction. Older grouped documents retain no
inferred contrast. A minimum combined with pooled-query weighting is an explicit
refusal while the native pooled reduction cannot express that minimum. Missing
report cells retain their absence; a plot interface requiring a finite group mean
refuses that plot rather than dropping the group or drawing zero.

Figure plots, methods and participant exports read explicit report views. The
participant export selects the first Participant D panel's declared scale, or the
first declared scale when the figure has no such panel; its metadata and README
state that choice. A coincident numerical mean never determines scale identity.

## First-analysis interaction slice

The native command and desktop journeys start with an empty project, import actual
stored CSV and image bytes, admit the dataset, choose an analysis preset, complete
the bounded preview and save the first revision/run. `StartAnalysis` creates an
initial working draft with a typed seed; no saved revision exists until
`SaveAndRun`. Returning edits to the seed retains that initial draft. The decision
is recorded in bead `q-initial-analysis-draft`.

Initial drafts require document/scientific-content/journal versions 7/3/4.
Existing drafts retain their original bytes and earliest supported versions. Older
readers and writers refuse the new variant, including relabelled envelopes.

The stored-project port accepts operations without scheduling or waiting for IO
under its acceptance lock. Its single worker preserves journal-before-save order;
the winning close drains accepted work and releases that worker despite caller
interruption. This prevents autosave and native source callbacks from deadlocking
the window during admission.

`NativeGoldenCommandFxSuite` exercises the admission, preset, Save & run and bundle
export controls. Import-dialog answers, navigation, reporting and panel setup use
explicit application commands. Its rows, report, source references and export bytes
must equal a separate `NativeCommandJourneyScenario` run.
`NativeCommandJourneySuite` also checks the direct-library/SCORES oracle, cold
reopen and actual stored bundle files. No fixture backend supplies their results.

`NativeExecutionSafetySuite` covers corrupted source bytes, tampered and stale
receipts, native cancellation, and real older completion events delivered after a
newer run completes. The latest requested run remains current; completion never
implicitly changes the shown run. New runs retain unbound declarations when no
native storage sink is supplied. Project-backed native routes publish
bindings only after the archive delivery below succeeds.

This slice does not qualify the full adversarial catalogue, every formerly
fixture-only ticket, or hosted checks. Those remain parent acceptance requirements.

## Verified native archive delivery

Scientific completion and archive storage are separate. The execution service
publishes its actual `Succeeded` and `Ready` events first, then runs optional native
delivery outside the tracker lock and event publisher. A stored fact identifies
the exact observed successful job and completed run; it does not select Show.
Failure leaves truthful completed science with an unbound archive and an explicit
artifact refusal. Fake/demo sessions and native sessions without a storage sink
produce no fabricated artifact facts.

The producer exports only retained native work, never starting a recomputation to
answer an artifact request. The library writes and resolves the plan, admitted
input, admission ledger, packed result and every density payload as one verified
closure. The source-record semantic identity, canonical plan/input/result digests,
stored entry byte hashes, manifest address and Studio index hash remain distinct.
Canonical digests use the library codecs, including their portable binary JSON
rendering. `RunRef.archive` continues to mean canonical decoded `StudyResult`;
`Recipe.input` continues to mean parsed source-record identity. The canonical input
binding is independently persisted in the typed facts and native archive.

`ProjectSession` owns archive writes under its writer lock. It validates the exact
target, writes entries before the future-bound index, reads and verifies them, then
acknowledges the original facts. The ordinary journal/save path applies one atomic
`BindCompletedArtifacts` command. Identical facts are idempotent; conflicting
scope, recipe, source, plan or result bindings refuse. A host sink returning altered
facts cannot publish a binding. Cold archive loading verifies stored lengths and
hashes, library relations and canonical identities without a backend. The decision
is recorded in bead `q-native-stored-completion`.

The binding command requires journal version 5; earlier readers and writers refuse
it, while historical pins retain their original versions and bytes. Existing
document and scientific-content vocabulary is unchanged. An interrupted store can
leave explicit orphan bytes, and an existing incompatible index collides rather
than being silently rewritten.

Whole-archive export uses explicit density-cell, structural-row, entry and byte
budgets. Oversized closures refuse without dropping maps or rows. Empty admitted
inputs currently refuse export when they lack a source frame for recipe checking.
The current runner produces a plain `StudyResult`; this route makes no retroactive
stamped-completion claim. Public backend transport of artifact payloads and a
stamped-runner migration remain separate slices.

## Native archive readback

Project-backed native sessions can restore a completed run from its verified
stored closure. The package retains the decoded native plan, input, admission
ledger and result together. Rebuilding the read context prepares and counts the
library's schedules; it never executes or scores the study again. The current
run, analysis, dataset, recipe and declared bindings must agree before publication.

Archived scientific evidence is separate from live admission, stimulus availability
and verbatim CSV text. Summary, query, report, pair, map and coordinate reads use
the stored scientific values. A request for original source text reads and checks
the source lazily; unavailable text is an explicit refusal. Admission and image
availability still come from the actual source and asset ports.

Restoration has a typed loading value and one shared operation per run. Concurrent
readers wait for the same result, cancellation closes their wait, and archive IO
runs outside the backend's submission/document mutex. Loading an archive creates
no scientific job and changes no completed run lifecycle. Restored provenance
names the verified manifest's byte address, independently of the result's canonical
digest; this remains a plain-result route without a stamped completion claim.

Genuinely absent or pruned archives and legacy storage retain the existing
recomputation path and its provenance. A bound result alone does not prove that a
native package was stored. Present incomplete or corrupt native storage refuses
without silently recomputing. Native factory capabilities remain local; wire
compatibility covers the new loading/refusal and provenance values. The decision
is recorded in bead `q-native-archive-readback`.

Native binding facts version 2 bind the complete dataset content digest and the
exact recorded admission policy, including legacy absence. This mirrors
`RealRegistry` immutability and detects cold documents that reuse an ID with
changed sources, units, geometry, column/image mapping, attributes or admission
choices. Lifecycle and ledger-binding bookkeeping remain outside that definition.
New native exports always carry this evidence; journal version 6 records these
binding commands. No document, science or protocol vocabulary changes.

Version-1 facts and journal-5 bindings retain their original bytes and remain
readable. Explicit facts lifting carries absent definition evidence as null; it
cannot manufacture proof. A present legacy native package without the original
definition refuses restoration with a re-run instruction. Re-running from verified
sources can produce a new package. Missing/pruned archives retain the existing
ordinary recomputation route. The migration is tracked in mote
`bd-01M49A48HB52R4AT20V94ZP6PY`.

## Remaining acceptance

Each slice must retain its focused test receipts and independent review. The parent
stays open until the final integrated candidate has all of the following:

1. Native placement and correction admission agree with the importer, including
   off-screen exclusion, quarantine, conflicting rules and unplaced records.
2. Desktop and headless sessions consume native backend and navigation ports, own
   their resources, and follow actual jobs and document revisions.
3. Every real backend conformance test runs, with no silently omitted operation.
4. The golden and adversarial routes compare native scores and sources with the
   direct library and pinned native score fixture. Illustrative mock scores remain
   fixture display data.
5. Save/reopen and exports preserve their declared artifact and numerical contracts.
6. Fake-closed ticket acceptance is rechecked against the real backend, and the
   final library/Studio boundary, style, API, consumer and hosted checks are recorded
   on an exact candidate SHA and tree.

## Representation limits

The current single-reference query/preview row refuses multiple matched references
rather than choosing one. Query rows whose scales have different scored/failed
states refuse that aggregate representation; all-failed rows retain a diagnostic
for every scale in declared order. Per-scale inspection and native reports retain
the underlying data. Missing declared
response attributes are explicit row refusals. A policy around a fixation cross
requires its position in the recipe or dataset; the native backend does not infer it.

Recomputed document results remain marked with the producing eyes4s version. A bound
result archive must have the recorded canonical digest, and a bound saved plan must
agree with the native plan its recipe constructs. A digest mismatch cannot become
an original or current result.
