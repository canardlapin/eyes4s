# S3.7 · Swap to the real eyes4s backend: slice plan

Ticket `bd-01M3DPFHY9YW5BPSJQ8VBBXHVN`. Base: main `cdc25580`, protocol 1.8. Protocol 1.9
(`pairRows`) is on `p0-pairrows`.

S3.7 implements `StudyBackend[F]` over eyes4s. Every acceptance criterion closed on
`FakeStudyBackend` must also pass on the real backend. This plan splits that work into slices of
at most half a day. Each slice lands and closes on its own, under `bd-01M3DPFHY9YW5BPSJQ8VBBXHVN`.

## Rules every slice keeps

- **No science in studio.** The real backend calls the library and converts its values into the
  studio protocol types. It never re-derives a count, score, placement or density. Summing
  durations the library has already tallied, or counting rows of a library ledger, is bookkeeping.
  Anything that decides what a fixation, trial or pair *is* stays in eyes4s.
- **Failures are typed values.** Every eyes4s refusal becomes a `BackendError` that names its
  operands: either an existing case, or a new case added in the slice, with its stable code and a
  protocol bump when it changes the wire. An effect fails only on a defect of the backend itself.
- **R is never a dependency.** Scores the real backend serves are compared with
  `fixtures/studio-golden/SCORES.json` (S0.7b), never with an R run.
- **Placement.** `RealStudyBackend` lives in `studio-core` shared sources (JVM and Scala.js).
  `studio-core` gains a compile dependency on `eyes4s-io`, which is cross-built and allowed to use
  effects; today `studio-core` reaches io only from its JVM tests.
  - The backend reads no files. Its datasets arrive as `DatasetRevisionSpec`s from the studio
    document, and its source contents arrive through a `SourceContents[F]` port that the host
    provides: studio-desktop reads files, and JVM tests serve `fixtures/studio-golden`.
  - `studio-app` stays pure. It never calls the backend's library code directly; it only receives
    `StudyBackend` responses.
- **Conformance.** `BackendConformanceSuite` is reused unchanged. The real-backend subclass
  (`RealBackendConformanceSuite`, a JVM test that reads the golden files) runs the subset of tests
  its slices support. That subset is an explicit list that grows by slice, so a test is never
  silently skipped. The fake keeps running every test.

## Slices

1. **Skeleton, admission and ledger (now).**
   - `RealStudyBackend[F]` over registered `DatasetRevisionSpec`s, `AnalysisRevisionSpec`s and a
     `SourceContents[F]` port.
   - `admission` and `ledger` call eyes4s-io under the revision's recorded mapping, units,
     geometry and admission choice.
   - The image-window tallies use `WindowTally.window`. Images found and missing are computed
     against the host's stimulus listing.
   - Every operation not yet implemented answers a typed refusal (`Unavailable` naming the
     revision, run or job). It never fakes data.
   - Unknown dataset, revision, run and job refusals match the fake's codes.
   - `RealBackendConformanceSuite` runs three tests: "admission reports the FIXTURE.md inventory
     and window totals", "the ledger pages through every inventory trial once and agrees with
     admission", and the dataset/revision half of "refusals are values…".
   - Inventory refusals become `BackendError.InventoryRefused` through `InventoryIssue.of`.
2. **Revision → `StudyPlan` and the static preview.** Build the plan from `AnalysisRevisionSpec`,
   refuse a recipe the bound plan disagrees with, and serve `preview` / `previewRows` from
   `StudyPreview`. Adds the conformance test "the preview's counts agree with its rows". Blocked
   on the preview-digest protocol change unless the stamp gains it in this slice (needs the lead's
   call on the protocol owner).
3. **Preview paging and submitting a ready preview** (needs 1.9 `pairRows`).
4. **Execution and progress over eyes4s-fs2.** Adds the subscription and cancellation
   conformance tests; `finish` waits for the real job.
5. **Results, queries and inspection.** Adds the result and inspection conformance tests; scores
   are checked against SCORES.json once S0.7b freezes it.
6. **Provenance** (after UI-G G3 and the G1 record retype).
7. **Trial views and source records** (after the core placement bead).
8. **Density grids for Figures panel C** (protocol minor bump plus a `StudyBackend` method).
9. **Descriptors** (after CR6), the full conformance and the E2E-01 / adversarial runs on the
   real backend, and the PR list re-checking every fake-closed ticket's real-backend acceptance
   criterion.
